# 암 유전체 데이터 구조 및 변이 표기 전처리 조사

## 1. 문서 목적

암환자 유전체 변이 정보를 활용한 암종 분류 모델을 개발하기에 앞서 다음 사항을 확인한다.

- `train.csv`의 데이터 구조와 컬럼 의미
- 유전자 컬럼에 기록된 단백질 변이 표기 유형
- 표준·비표준 변이 문자열의 해석 범위
- HGVS 표기법으로 변환할 수 있는 범위와 한계
- 모델링을 위한 변이 문자열 전처리 방향


---

## 2. 데이터 개요

### 2.1 파일 구조

| 항목 | 확인 결과 |
|---|---:|
| 전체 샘플 수 | 6,201 |
| 전체 컬럼 수 | 4,386 |
| 유전자 컬럼 수 | 4,384 |
| 암종 클래스 수 | 26 |
| ID 중복 | 없음 |
| 빈 문자열 형태의 결측값 | 없음 |

`train.csv`는 다음 세 종류의 컬럼으로 구성된다.

| 컬럼 | 의미 | 모델링 시 역할 |
|---|---|---|
| `ID` | 샘플별 고유 식별자 | 일반적으로 입력 특성에서 제외 |
| `SUBCLASS` | 해당 샘플의 암종 | 예측 타깃 |
| `A2M`~`ZYX` | 유전자별 단백질 수준 변이 정보 | 모델 입력 특성 |

각 행은 하나의 유전체 샘플을 의미한다. 공식 설명은 이를 샘플로 정의하므로, 추가 메타데이터 없이 각 행을 반드시 환자 한 명과 동일하다고 단정하지 않는다.

### 2.2 유전자 컬럼 값

각 유전자 컬럼에는 주로 다음 값이 기록되어 있다.

```text
WT
R132H
D623D
E237*
K16fs
Q369* I368N
```

- `WT`: Wild Type의 약자로, 데이터의 검사·기록 기준에서 해당 유전자에 변이가 기록되지 않았음을 의미한다.
- 그 외 문자열: 아미노산 치환, 종결코돈 생성, 프레임시프트 등 단백질 수준의 변이 정보를 축약해서 나타낸다.
- 한 셀에 공백으로 구분된 복수의 변이가 기록되기도 한다.

`WT`를 “유전자 전체에 어떤 변이도 존재하지 않는다”로 절대적으로 해석해서는 안 된다. 검사 범위, 변이 검출 및 필터링 기준에서 **기록된 변이가 없음**으로 해석하는 것이 안전하다.

### 3.2 클래스 불균형

## 4. 변이 표기 유형

`WT`가 아닌 셀을 공백 기준으로 나눈 결과 총 255,164개의 개별 변이 표기가 확인되었다.

| 유형 | 대표 형식 | 예시 | 개수 |
|---|---|---|---:|
| 미스센스 치환 | `A숫자B` | `R132H`, `V600E` | 164,740 |
| 동의 변이 | `A숫자A` | `D623D`, `G592G` | 66,883 |
| 종결코돈 생성 | `A숫자*` | `E237*`, `R213*` | 13,289 |
| 프레임시프트 | `문자열+숫자+fs` | `K16fs`, `GD693fs` | 9,833 |
| 구간·복합 치환 | `숫자_숫자서열>서열` | `91_92NH>KY` | 239 |
| 결실 | `A숫자del`, `숫자del` | `R649del`, `249del` | 3 |
| 비표준·부분 표기 | 다양한 형식 | `-287fs`, `*261*` | 177 |

위 개수는 문자열 패턴으로 분류한 결과이며, 실제 DNA 변이 이벤트 수와 일치하지 않을 수 있다.

### 4.1 미스센스 치환

형식:

```text
기준 아미노산 + 단백질 위치 + 변경 아미노산
```

예:

```text
R132H
```

- `R`: 기준 아미노산 Arginine
- `132`: 단백질의 132번 위치
- `H`: 변경 아미노산 Histidine

따라서 132번 위치의 Arginine이 Histidine으로 치환된 것으로 해석한다.

### 4.2 동의 변이

예:

```text
D623D
G592G
```

앞뒤의 아미노산 문자가 동일하다. DNA 염기 변화는 있을 수 있지만 번역된 아미노산은 변하지 않은 동의 변이로 해석한다.

단백질 변화만 고려하면 영향이 작아 보일 수 있으나, 암종별 돌연변이 패턴을 반영할 가능성이 있으므로 성능 검증 없이 제거하지 않는다.

### 4.3 종결코돈 생성

예:

```text
E237*
R213*
```

`*`는 종결코돈을 뜻한다. 예를 들어 `E237*`는 237번 Glutamic acid가 종결코돈으로 변경된 단백질 수준의 stop-gain 또는 nonsense 변이로 해석한다.

### 4.4 프레임시프트

예:

```text
K16fs
P700fs
GD693fs
SGL1823fs
```

`fs`는 frameshift를 의미한다. DNA의 삽입·결실로 번역 읽기 틀이 변경되어 이후 아미노산 서열과 단백질 길이가 달라질 수 있다.

#### `K16fs`

안전하게 해석할 수 있는 범위는 다음과 같다.

> 16번 Lysine 부근부터 읽기 틀이 변경되는 단백질 수준의 프레임시프트 변이

현재 표기만으로는 다음 정보를 알 수 없다.

- 새 읽기 틀에서 처음 생성되는 아미노산
- 새로운 종결코돈까지의 거리
- 변이를 유발한 정확한 DNA 삽입·결실
- 최종 단백질 길이

#### `GD693fs`

`693`과 `fs`를 통해 693번 위치 부근의 프레임시프트라는 점은 추출할 수 있다. 그러나 `GD`가 기준 아미노산과 변경 아미노산을 의미하는지, 여러 아미노산 서열을 의미하는지는 데이터 설명만으로 확정할 수 없다.

따라서 다음처럼 보수적으로 처리한다.

```text
raw_value: GD693fs
effect_type: frameshift
position: 693
reference_aa: unresolved
alternate_aa: unresolved
parse_quality: nonstandard
```

근거 없이 `G693Dfs` 또는 `p.(Gly693Aspfs)`로 재배열하지 않는다.

### 4.5 구간·복합 치환

예:

```text
91_92NH>KY
355_356QG>H*
1529_1530AL>AL
```

`91_92NH>KY`는 91~92번 위치의 `NH` 서열이 `KY`로 교체된 것으로 해석할 수 있다. 정식 HGVS 관점에서는 단순 치환보다 deletion-insertion(`delins`)에 가깝다.

`355_356QG>H*`는 355~356번의 `QG`가 `H`와 종결코돈으로 교체된 복합 변이로 볼 수 있다.

`1529_1530AL>AL`처럼 변경 전후 단백질 문자열이 동일한 경우에는 동의성 복합 변이 또는 데이터 변환 과정의 산물일 수 있으므로 원본 DNA 변이 없이 확정하지 않는다.

### 4.6 결실

파일에서 다음과 같은 표기가 확인되었다.

```text
249del
490del
R649del
```

- `R649del`: 649번 Arginine의 결실로 해석 가능
- `249del`, `490del`: 기준 아미노산 문자가 생략된 결실 표기

### 4.7 비표준·부분 표기

| 예시 | 안전한 해석 | 한계 |
|---|---|---|
| `-287fs` | 287번 위치 부근 프레임시프트 | 기준 아미노산 누락 |
| `*214fs` | 종결코돈 관련 변이 및 `fs` 정보 포함 | stop-loss 또는 extension 가능성 |
| `IW*44fs` | 44번 위치, `fs`와 `*` 포함 | 문자 순서와 의미가 비표준 |
| `*261*` | 종결코돈에서 종결코돈으로 기록 | stop-retained 또는 변환 산물 가능성 |
| `GD693fs` | 693번 위치 부근 프레임시프트 | `GD`의 역할 미확정 |

비표준 표기는 “전처리에 시간이 오래 걸리는 값”인 동시에, 원본 정보가 없으면 시간을 들여도 완전한 해석이 불가능할 수 있는 값이다.

## 5. 한 셀에 기록된 복수 변이

한 유전자 셀에 변이가 여러 개 들어 있는 경우 공백으로 구분되어 있다.

```text
Q369* I368N
F513F H641Y P913L
I758S P700fs
```

| 셀 유형 | 개수 |
|---|---:|
| 단일 변이 표기 셀 | 196,867 |
| 복수 변이 표기 셀 | 22,026 |
| 한 셀의 최대 공백 분리 표기 수 | 64 |

일부 셀에서는 같은 변이 목록이 반복된다. 따라서 다음 두 특성을 구분해서 생성할 수 있다.

- 원문에 기록된 변이 표기 수
- 중복을 제거한 고유 변이 표기 수

중복이 데이터 오류인지 별도의 사건을 의미하는지는 현재 정보만으로 확정할 수 없으므로 원본 문자열을 보존한다.

## 6. HGVS 변환 검토

### 6.1 현재 표기의 성격

현재 데이터는 정식 HGVS가 아니라 단백질 수준의 변이를 압축한 문자열이다. 표준적인 문자열은 HGVS 형태로 부분 정규화할 수 있다.

| 원본 | 단백질 HGVS 후보 |
|---|---|
| `R132H` | `p.(Arg132His)` |
| `D623D` | `p.(Asp623=)` |
| `E237*` | `p.(Glu237Ter)` |
| `K16fs` | `p.(Lys16fs)` |
| `R649del` | `p.(Arg649del)` |

그러나 완전하고 고유한 HGVS 표기에는 기준 서열 accession과 버전이 필요하다.

```text
NP_XXXXXX.X:p.(Lys16fs)
```

### 6.2 형식 정규화와 검증된 변환의 차이

#### 형식 정규화

```text
K16fs → p.(Lys16fs)
```

문자 규칙만으로 가능하지만 실제 기준 단백질의 16번이 Lysine인지 확인하지 않은 상태이다.

#### 검증된 변환

다음 절차가 필요하다.

1. 유전자에 사용할 기준 transcript 선정
2. 연결된 기준 단백질 accession과 버전 선정
3. 표시된 위치의 기준 아미노산 확인
4. 변경 아미노산과 변이 유형 확인
5. HGVS 후보 생성 및 검증

가능하면 다음 우선순위로 transcript를 선택한다.

```text
MANE Select
→ MANE Plus Clinical
→ RefSeq Select
→ Ensembl canonical transcript
```

하나의 유전자에는 여러 transcript와 단백질 isoform이 존재할 수 있다. 같은 위치 번호라도 isoform에 따라 기준 아미노산이 다르거나 해당 위치가 존재하지 않을 수 있다.

### 6.3 프레임시프트의 추가 한계

`K16fs`를 기준 단백질과 대조하여 16번이 Lysine이라는 점을 확인하면 다음 축약형 후보를 만들 수 있다.

```text
NP_XXXXXX.X:p.(Lys16fs)
```

그러나 다음과 같은 완전한 표기를 만들려면 원본 DNA 변이가 필요하다.

```text
NP_XXXXXX.X:p.(Lys16ArgfsTer12)
```

필요한 추가 정보:

- 정확한 cDNA 또는 genomic 삽입·결실
- 새 읽기 틀에서 처음 생성되는 아미노산
- 새 종결코돈까지의 거리

즉 기준 단백질 서열만 대조해도 원본에 없는 정보까지 복원할 수는 없다.

### 6.4 원본 DNA 변이의 필요성

정확한 HGVS 생성에는 다음 중 하나가 필요하다.

- VCF의 염색체, 위치, `REF`, `ALT`
- 원본 MAF의 genomic 및 coding 변이 정보
- `NM_...:c.` 형식의 cDNA 변이
- 기준 서열과 실제 변이 서열

원본 MAF 또는 VCF를 확보할 수 있다면 단백질 축약 문자열을 역으로 추정하지 않고 DNA 변이에서 HGVS를 새로 생성하는 것이 가장 정확하다.

## 7. HGVS 관련 도구

### 7.1 VariantValidator

주요 기능:

- HGVS 표기 검증 및 가능한 경우 교정
- transcript와 genomic 변이 사이의 매핑
- VCF와 HGVS 사이의 변환
- Gene to Transcript 검색
- Batch Validator 제공

VariantValidator는 원본 genomic 또는 cDNA 변이가 있을 때 가장 유용하다. 현재 데이터의 `K16fs`만 넣어 원인 DNA 변이를 복원하는 용도로 사용할 수는 없다.

예를 들어 RPL22의 RefSeq 조합은 다음과 같다.

```text
NM_000983.4 → NP_000974.1
```

다음 입력은 단백질 HGVS 후보를 시험하는 용도로 사용할 수 있다.

```text
NP_000974.1:p.(Lys16fs)
```

단, 이는 “RPL22의 해당 기준 단백질에서 16번 위치가 Lysine이며 대회 표기와 동일한 위치 체계를 사용한다”는 가정을 포함한다. 검증 오류가 발생하면 값을 억지로 고쳐 맞추지 않는다.

### 7.2 Mutalyzer

주요 기능:

- HGVS 문법 및 기준 서열 검증
- 변이 표기 정규화
- 기준 서열 사이의 위치 매핑
- 기준 서열과 관측 서열을 비교한 HGVS 생성

VariantValidator 결과를 Mutalyzer로 교차 검증할 수 있다. 그러나 Mutalyzer 역시 원본에 없는 frameshift 세부 정보나 모호한 접두부의 의미를 자동으로 복원할 수는 없다.

### 7.3 Ensembl VEP 및 Variant Recoder

Ensembl VEP는 genomic 변이의 transcript·단백질 영향을 주석하는 대표적인 도구이다. Variant Recoder는 variant ID, HGVS, SPDI, VCF 등의 표기 변환에 사용할 수 있다.

현재 데이터의 `GD693fs`처럼 비표준적인 단백질 축약 표기는 VEP에 직접 입력해도 원본 DNA 변이를 정확하게 복원할 수 없다.

재현 가능한 분석을 위해 다음 항목을 기록해야 한다.

- 참조 유전체: GRCh37 또는 GRCh38
- VEP 및 cache 버전
- FASTA 버전
- transcript source: Ensembl, RefSeq 또는 merged
- MANE/Canonical transcript 선택 기준

## 8. 전처리 원칙

### 8.1 원본 보존

모든 변이 문자열은 `raw_value`로 보존한다. 비표준 표기를 임의로 교정하거나 문자의 순서를 재배열하지 않는다.

### 8.2 파싱 결과

각 변이 또는 유전자 셀에서 다음 정보를 추출한다.

```text
raw_value
is_wt
event_count_raw
event_count_unique
effect_type
position_start
position_end
reference_aa
alternate_aa
has_frameshift
has_stop
parse_quality
```

### 8.3 초기 변이 유형

```text
WT
MISSENSE
SYNONYMOUS
STOP_GAIN
FRAMESHIFT
COMPLEX_REPLACEMENT
DELETION
NONSTANDARD
```

### 8.4 파싱 신뢰도

```text
STANDARD
PARTIAL
NONSTANDARD
UNRESOLVED
```

예:

| 원본 | 유형 | 신뢰도 |
|---|---|---|
| `R132H` | `MISSENSE` | `STANDARD` |
| `K16fs` | `FRAMESHIFT` | `PARTIAL` |
| `GD693fs` | `FRAMESHIFT` | `NONSTANDARD` |
| `-287fs` | `FRAMESHIFT` | `UNRESOLVED` |

### 8.5 모델 특성 후보

초기 모델에서는 다음 수준의 특성을 비교할 수 있다.

1. 유전자별 `WT`/변이 여부
2. 유전자별 변이 유형
3. 샘플별 전체 변이 유전자 수
4. 샘플별 missense, synonymous, stop-gain, frameshift 개수
5. 복수 변이 및 비표준 변이 개수
6. 자주 발생하는 유전자-변이 조합

고유 변이 문자열의 종류가 매우 많으므로 모든 원문 문자열을 단순 one-hot encoding하면 차원이 급격히 증가할 수 있다. 우선 유전자별 변이 유무와 변이 유형을 사용한 베이스라인을 구축한 뒤 원문 토큰 특성의 추가 효과를 검증한다.
